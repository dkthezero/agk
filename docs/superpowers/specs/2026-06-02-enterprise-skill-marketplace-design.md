# Design Spec: Enterprise Skill Marketplace (P7)

**Date:** 2026-06-02
**Status:** Draft — Pending Review
**Epic:** Enterprise Skill Marketplace
**Parent:** `docs/proposals/enterprise-feature-pack.md` (reframed)
**Market Research:** `docs/proposals/enterprise-skills-marketplace-research.md`

---

## 1. Executive Summary

The Enterprise Feature Pack is reframed as **Enterprise Skill Marketplace** — AGK evolves from a skill package manager into the universal client for internal team marketplaces. A Skill Marketplace is simply a git repository acting as a self-contained vault — no hosting infrastructure required.

The Epic ships in three phases:

| Phase | Release | Feature | Core Value |
|---|---|---|---|
| **1** | v0.4.0 | Skill Marketplace & Team Sync | "New hire runs `agk sync` → fully set up" |
| **2** | v0.4.1 | Policy & Compliance | "CISO controls which skills can be installed" |
| **3** | v0.4.2 | Telemetry & Reporting | "PM sees which skills the team actually uses" |

**Future (v0.5+):** Registry Integration (JFrog, SkillReg), Skill Signing & Provenance, Semantic Search, Contributor Workflow.

---

## 2. Key Design Decisions

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Skill Marketplace = git repo as vault** | No hosting required. Enterprises already have GitHub/GitLab. One repo, one access point, no N-vault access problem. |
| 2 | **Three config files: `config.toml` / `team.toml` / `.agk/vault.toml`** | Separation of concerns: personal config, team mandates, vault metadata. All live in `.agk/`. `vault.toml` generated by `agk vault init`. |
| 3 | **`vault.toml` does NOT list skills** | AGK's existing scan-based approach (scanning `skills/`, `instructions/`, `mcps/` folders) already discovers assets. No need to manually enumerate. |
| 4 | **Auto `.gitignore` for `config.toml`** | When `team.toml` is present, AGK creates `.agk/.gitignore` with `config.toml` to keep personal config out of git. `team.toml` is committed (team-shared). |
| 5 | **Policy is local-only enforcement** | No central server required. Policies in `policy.toml`, pushed via MDM/git/config management. Matches AGK's existing config-driven approach. |
| 6 | **Skill Signing deferred** | GPG signing is documented in the proposal but not implemented until client demand. The `PolicyConfig` model includes `require_signature` for future use. |
| 7 | **Team telemetry is opt-in** | Privacy-preserving by design. No PII. Team report contains only skill names, invocation counts, and anonymized active user counts. |
| 8 | **`[Team]` badge in TUI** | F3 toggles team membership (adds/removes from `team.toml`). Space toggles personal install. Unchecking `[Team]` removes files but not the `team.toml` requirement — user has opted out locally. |
| 9 | **`--provider` flag on sync** | `agk sync --provider claude` targets a specific provider. Without flag, sync installs to all active providers. |
| 10 | **`enforce_team_vaults_only`** | When `team.toml` is present and this policy flag is set, only team vaults are allowed. CISO can mandate "no personal vault additions." |

## 3. Phase 1: Skill Marketplace & Team Sync (v0.4.0)

### 3.1 User Stories

**Team Lead:**
- As a team lead, I want to create a Skill Marketplace repo so my team has a single source of truth for approved skills.
- As a team lead, I want to add skills from other vaults to our marketplace so team members get everything from one place.
- As a team lead, I want to run `agk team add` to add a skill to team requirements so it auto-installs for everyone.
- As a team lead, I want to run `agk team add-vault` to add a vault to our marketplace so team members get auto-access to approved vaults.

**Team Member:**
- As a new team member, I want to run `agk sync` after cloning the repo so all team skills are installed automatically.
- As a team member, I want to install personal skills that aren't in the team config so I can extend my setup.
- As a team member, I want to see `[Team]` vs `[You]` badges so I know which skills are mandated vs personal.
- As a team member, I want to opt out of a team skill locally without modifying `team.toml` so my personal setup differs from team mandates.

### 3.2 Three Config Files

| File               | Location | Purpose | Git-tracked |
|--------------------|---|---|---|
| `.agk/config.toml` | Workspace | Personal installed assets, providers, personal vaults | **No** (auto-gitignored when team.toml present) |
| `.agk/team.toml`   | Workspace | Team membership, required vaults, required skills | **Yes** (committed to repo) |
| `.agk/vault.toml`  | Inside vault repo's `.agk/` dir | Vault metadata, dependencies on other vaults | **Yes** (committed to vault repo) |

#### 3.2.1 `team.toml` Schema

```toml
# Auto-managed by `agk team` commands
# Stored at .agk/team.toml
name = "frontend-platform"
source = "github.com/acme-org/frontend-app"
branch = "main"

# Vaults automatically attached on `agk sync`
[[vaults]]
identity = "acme-platform"
type = "github"
url = "https://github.com/acme-org/platform-skills"
branch = "main"

[[vaults]]
identity = "acme-mcp"
type = "github"
url = "https://github.com/acme-org/mcp-servers"

# Skills auto-installed on `agk sync`
[[requirements]]
identity = "acme-org/react-conventions"
vault = "acme-platform"
kind = "skill"

[[requirements]]
identity = "acme-org/api-testing"
vault = "acme-platform"
kind = "skill"
version_constraint = ">= 2.0.0"

[[requirements]]
identity = "acme-org/api-gateway"
vault = "acme-mcp"
kind = "mcp"
```

#### 3.2.2 `vault.toml` Schema

```toml
# Inside a vault repo (e.g., github.com/acme-org/platform-skills/.agk/vault.toml)
# Generated by `agk vault init`
name = "platform-skills"
description = "Acme Frontend Platform Skills"
version = "1.0.0"

# External vaults this vault depends on (for dependency resolution)
[[dependencies]]
identity = "clawhub-public"
type = "clawhub"
url = "https://clawhub.ai"

# Skills are auto-discovered by scanning the vault repo's folder structure
# (No skill listing needed — AGK scans skills/, instructions/, mcps/ automatically)
```

#### 3.2.3 Auto `.gitignore`

When `team.toml` is present in `.agk/`, AGK auto-creates/updates `.agk/.gitignore`:

```gitignore
# Personal workspace config — not committed
config.toml
```

This ensures `team.toml` is committed (team-shared) while `config.toml` stays local (personal).

### 3.3 Domain Models

```rust
// src/domain/team.rs

/// Team membership configuration stored in .agk/team.toml
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize, Default)]
pub struct TeamConfig {
    pub name: String,
    pub source: Option<String>,
    pub branch: Option<String>,
    pub vaults: Vec<TeamVault>,
    pub requirements: Vec<TeamRequirement>,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct TeamVault {
    pub identity: String,
    pub vault_type: String,
    pub url: String,
    #[serde(default = "default_branch")]
    pub branch: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub path: Option<String>,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct TeamRequirement {
    pub identity: String,
    pub vault: String,
    #[serde(default = "default_kind")]
    pub kind: AssetKind,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub version_constraint: Option<String>,
}

/// Vault metadata stored inside vault repos (.agk/vault.toml)
/// Generated by `agk vault init`
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct VaultManifest {
    pub name: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub description: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub version: Option<String>,
    #[serde(default)]
    pub dependencies: Vec<VaultDependency>,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct VaultDependency {
    pub identity: String,
    pub dep_type: String,
    pub url: String,
}

/// Tag applied to installed skills in config.toml to indicate team mandate.
/// Stored as `source = "team"` or `source = "personal"` in each vault section's
/// item entry. When absent, defaults to "personal" (backward compatible).
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum AssetSource {
    #[serde(rename = "team")]
    Team,
    #[serde(rename = "personal")]
    Personal,
}

// Example config.toml entry with AssetSource:
// [[vaults.acme-platform.skills]]
// identity = "acme-org/react-conventions:2.1.0:a13c9ef042"
// source = "team"
//
// [[vaults.personal.skills]]
// identity = "my-debug-helper:--:9ac00ff113"
// source = "personal"
```

### 3.4 CLI Commands

```bash
# Initialize a vault repo (creates .agk/vault.toml + standard folders)
agk vault init                          # name defaults to current folder name
agk vault init --name "platform-skills" # explicit name
# Creates:
#   .agk/vault.toml    (vault metadata, default name from folder)
#   skills/            (skill packages)
#   instructions/      (instruction packages)
#   mcps/              (MCP server configs)
#   profiles/          (profile templates)

# Initialize team config in current workspace
agk team init --name "frontend-platform"

# Add a vault to the team marketplace
agk team add-vault acme-platform \
  --type github \
  --url https://github.com/acme-org/platform-skills \
  --branch main

# Add a skill requirement to the team
agk team add acme-org/react-conventions --vault acme-platform --kind skill

# Remove a skill from team requirements
agk team remove acme-org/react-conventions

# Show diff between team requirements and installed state
agk team diff

# Show team status
agk team status
# Output: [Team] 15/15 required skills installed ✓ | 3 personal

# Sync team requirements (auto-attach vaults, install missing, update outdated)
agk sync                          # sync all team requirements to all active providers
agk sync --provider claude        # sync to specific provider only
agk sync --dry-run                # show what would change without applying

# Update team.toml from source vault (pull latest team config)
agk team update
```

### 3.5 TUI Changes

| Element | Behavior |
|---|---|
| **Skills tab** | `[Team]` badge on team-mandated skills, no badge (or `[You]`) on personal skills |
| **Status bar** | `[Team] 15/15 ✓ | 3 personal` |
| **F3 key** | On a vault skill → toggles `[Team]` tag (adds/removes from `team.toml` requirements) |
| **Space key** | On a skill → toggles personal install (adds/removes from `config.toml` only) |
| **`s` key (sync)** | Shows diff summary modal before applying, includes provider selector |
| **Vault detail** | Shows `[Team Vault]` badge for vaults listed in `team.toml` |
| **Sync modal** | "3 new skills to install, 2 to update. Continue? [Y/n]" |

### 3.6 Sync Logic

```
agk sync:
1. Check for .agk/team.toml in workspace
2. If present:
   a. Read TeamConfig
   b. For each TeamVault:
      - If vault not attached → auto-attach
      - If vault needs refresh → refresh
   c. For each TeamRequirement:
      - If skill not installed → install
      - If skill installed but outdated → update
      - Tag as [Team] in config.toml
3. For previously-[Team] skills no longer in team.toml:
   - Warn: "X removed from team. Keep as personal? [y/N]"
   - If no → remove; If yes → untag [Team], keep installed
4. Auto-create .agk/.gitignore with config.toml if team.toml present
5. Report status: "[Team] 15/15 ✓ | 3 personal"

agk sync --provider claude:
  Same as above, but install/uninstall targets only the claude provider
```

### 3.7 Layer Merge: Team + Personal

```
Installed skills in workspace:
├── [Team] react-conventions    (from team.toml, auto-managed)
├── [Team] api-testing          (from team.toml, auto-managed)
├── [Team] api-gateway MCP     (from team.toml, auto-managed)
├── my-debug-helper             (personal, not in team.toml)
└── experimental-linter         (personal, not in team.toml)

Conflict resolution:
- Team removes a skill I still use personally:
  → agk sync warns: "react-conventions removed from team. Keep as personal? [y/N]"
  → If yes: skill becomes personal (untagged [Team])
  → If no: skill is removed

- Team adds a skill I already have personally:
  → agk sync upgrades the tag from personal → [Team]. No duplicate install.

- I try to remove a [Team] skill:
  → CLI: exit code 6 (TEAM_REQUIREMENT)
  → TUI: "This is a team-required skill. Remove from team.toml first, or opt out locally."

- Re-running agk sync after personal opt-out:
  → Re-installs the opted-out team skill (it's still mandated)
```

### 3.8 Flow Patterns

**Pattern A: Team with Team Vault (curated marketplace)**
```
Project Workspace (team.toml)
  └─ Team Vault (vault.toml) — self-contained skills + references to external vaults
       └─ External Vaults (GitHub, ClawHub, etc.)
```
Team lead creates a vault repo with `vault.toml`. This vault may contain skills directly or reference external vaults. `team.toml` points to this single Team Vault as the curated marketplace.

**Pattern B: Team without Team Vault (direct references)**
```
Project Workspace (team.toml)
  └─ External Vaults directly (GitHub, ClawHub, etc.)
```
Team lead lists external vaults directly in `team.toml`. Simpler setup, but team members need access to each external vault.

Both patterns work. AGK treats `team.vaults` as "the marketplace" — the curated set of approved sources for this team.

## 4. Phase 2: Policy & Compliance (v0.4.1)

### 4.1 User Stories

- As a CISO, I want to block skills from unapproved vaults so developers can't install unvetted code.
- As a platform engineer, I want an audit trail of every install/remove action so I can answer compliance questions.
- As a team lead, I want to enforce team-vaults-only so developers can't add personal vaults that bypass governance.
- As a developer, I want a clear error message when my install is blocked by policy so I know what to request approval for.

### 4.2 Domain Models

```rust
// src/domain/policy.rs

/// Policy configuration stored in policy.toml (global or workspace)
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize, Default)]
pub struct PolicyConfig {
    /// Only allow installs from these vaults (glob patterns)
    #[serde(default)]
    pub allow_vaults: Vec<String>,
    /// Block installs from these vaults (glob patterns)
    #[serde(default)]
    pub prohibit_vaults: Vec<String>,
    /// Skill name patterns that require review before install
    #[serde(default)]
    pub review_required_patterns: Vec<String>,
    /// Path to append-only audit log
    #[serde(skip_serializing_if = "Option::is_none")]
    pub audit_log: Option<PathBuf>,
    /// When team.toml is present, only allow installs from team vaults
    #[serde(default)]
    pub enforce_team_vaults_only: bool,
}

#[derive(Debug, Clone, PartialEq)]
pub enum PolicyViolation {
    BlockedVault { vault: String, rule: String },
    ReviewRequired { skill: String, pattern: String },
    UnsignedSkill { skill: String },
    TeamVaultOnly { vault: String },
}

#[derive(Debug, Clone, PartialEq)]
pub enum PolicyAction {
    Allow,
    Block(PolicyViolation),
    RequireReview(PolicyViolation),
}
```

### 4.3 Config Schema: `policy.toml`

```toml
# ~/.config/agk/policy.toml (global) or .agk/policy.toml (workspace)

[policy]
# Only allow skills from approved vaults (glob patterns)
allow_vaults = ["github.com/acme-org/*", "clawhub.ai/acme-org/*"]

# Block specific untrusted vaults (glob patterns)
prohibit_vaults = ["github.com/untrusted/*"]

# Skills with these patterns require review before install
review_required_patterns = ["network", "http", "api.*send", "ssh", "exec"]

# When team.toml is present, only allow installs from team vaults
enforce_team_vaults_only = true

# Append-only audit log (JSONL format)
audit_log = "~/.config/agk/audit.log"
```

**Merge behavior:** Global `policy.toml` is loaded first. Workspace `.agk/policy.toml` overrides/augments global rules. `allow_vaults` from workspace are added to global. `prohibit_vaults` from workspace are added to global. `enforce_team_vaults_only` in workspace overrides global.

### 4.4 Policy Evaluation

```
agk install or agk sync:
1. Load policy.toml (global → workspace merge)
2. Check if team.toml is present in workspace
3. For each skill about to be installed:
   a. Check vault against allow_vaults/prohibit_vaults (glob match)
   b. If enforce_team_vaults_only and team.toml present:
      - Only allow skills from team vaults
   c. Check skill name against review_required_patterns
   d. If any check fails:
      - TUI: Show modal "This skill violates policy: <reason>"
      - CLI: Exit code 4 (POLICY_VIOLATION)
      - Log to audit_log
4. If all checks pass:
   - Log install action to audit_log
   - Proceed with installation
```

### 4.5 Audit Log Format

JSONL (JSON Lines), append-only. One event per line.

```jsonl
{"ts":"2026-06-02T14:32:00Z","action":"install","identity":"react-conventions","vault":"acme-platform","scope":"workspace","source":"team","result":"allowed"}
{"ts":"2026-06-02T14:33:00Z","action":"install","identity":"data-exfiltrator","vault":"clawhub-public","scope":"workspace","source":"personal","result":"blocked","reason":"prohibited_vault:clawhub-public"}
{"ts":"2026-06-02T14:34:00Z","action":"install","identity":"ssh-helper","vault":"acme-platform","scope":"workspace","source":"team","result":"review_required","pattern":"ssh"}
{"ts":"2026-06-02T14:35:00Z","action":"remove","identity":"old-skill","vault":"acme-platform","scope":"workspace","source":"personal","result":"allowed"}
```

## 5. Phase 3: Telemetry & Reporting (v0.4.2)

### 5.1 User Stories

- As a platform engineer, I want to see which skills the frontend team actually uses so I can curate the marketplace effectively.
- As a PM, I want a CSV of skill usage by team so I can report adoption metrics.
- As a CISO, I want to know which skills haven't been used in 90 days so I can flag them for review.
- As a developer, I want assurance that my personal skill names and command arguments are never sent anywhere.

### 5.2 Domain Models

```rust
// src/domain/telemetry.rs (extend existing)

/// Team reporting configuration (opt-in)
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize, Default)]
pub struct TeamReportConfig {
    pub enabled: bool,
    pub team_id: Option<String>,
    pub upload_interval: Option<String>, // e.g., "24h"
    pub report_endpoint: Option<String>,
}

/// A single team usage report (no PII)
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct TeamReport {
    pub team_id: String,
    pub report_period_start: String,
    pub report_period_end: String,
    pub skills: Vec<SkillUsage>,
    pub mcps: Vec<McpUsage>,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct SkillUsage {
    pub name: String,
    pub invocations: u32,
    pub active_users: u32,
    pub source: AssetSource,
}

#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub struct McpUsage {
    pub name: String,
    pub invocations: u32,
    pub active_users: u32,
    pub source: AssetSource,
}
```

### 5.4 Team Report Payload

```json
{
  "team_id": "frontend-platform",
  "report_period": "2026-06-01T00:00:00Z/2026-06-02T00:00:00Z",
  "skills": [
    {"name": "react-conventions", "invocations": 150, "active_users": 8, "source": "team"},
    {"name": "my-debug-helper", "invocations": 12, "active_users": 2, "source": "personal"}
  ],
  "mcps": [
    {"name": "api-gateway", "invocations": 89, "active_users": 5, "source": "team"}
  ]
}
```

**Privacy guarantees:**
- No usernames. No machine names. No source code. No command arguments.
- Only skill names, invocation counts, and anonymized active user counts.
- `team_id` is a team identifier chosen by the platform team, not a personal identifier.
- Upload endpoint is company-hosted, not cloud.

### 5.5 CLI Commands

```bash

#   skill,team_invocations,active_users,source
#   react-conventions,150,8,team

# Show stale skills (not invoked in 90 days)
agk telemetry stale-report --threshold 90d

agk telemetry team-report --format csv --json
```

## 6. Cross-Cutting Concerns

### 6.1 Architecture Integrity

- No `.rs` file > 300 lines of non-test logic.
- `domain/` remains pure (no I/O).
- New features use existing `CoreCommand` / `CoreEvent` bus.
- Architecture tests pass with zero allowlists.
- New port traits follow existing patterns (`TeamConfigStorePort`, `PolicyStorePort`, `AuditLogPort`).

### 6.2 Testing Strategy

- **Unit:** `TeamConfig` serialization, `PolicyConfig` evaluation, audit log format, team report anonymization.
- **Contract:** CLI `--json` output shape for `team status`, `policy check`, `telemetry team-report`.
- **Integration:** Full TUI team sync flow via `TestBackend`. Policy violation blocking in TUI. Audit log file writes.
- **Process:** Mock vault for team sync tests. Policy engine tests with glob patterns.

### 6.3 Backward Compatibility

- `team.toml` absent → AGK works exactly as before (no team features).
- `policy.toml` absent → no policy enforcement (allow-all).
- `analytics.toml` without `team_report` → deserializes via `serde(default)`.
- Existing `config.toml` format unchanged (team tags added as `AssetSource` enum).

### 6.4 Dependency on Existing Features

| Phase | Depends On |
|---|---|
| Phase 1 (Team Sync) | GHES vault (v0.3.1), `VaultPort`, `ConfigStorePort`, `CoreCommand` bus |
| Phase 2 (Policy) | Phase 1 (team vaults are the allow-list source), `PolicyConfig`, `AuditLogger` |
| Phase 3 (Telemetry) | Phase 1 (`AssetSource` tags for team vs personal), existing `TelemetryStorePort` |

## 8. Risk Register

| Risk | Phase | Impact | Mitigation |
|---|---|---|---|
| **Team vault access: team members need access to all referenced vaults** | 1 | High | Recommend Pattern A (Team Vault as self-contained marketplace). Document Pattern B access requirements in best practices guide. |
| **`team.toml` merge conflicts** | 1 | Medium | `team.toml` is auto-managed by `agk team` commands. Manual edits are discouraged. Diff tool for conflict resolution. |
| **Policy `allow_vaults` glob patterns are too broad or too narrow** | 2 | Medium | `agk policy check --dry-run` to test policies before enforcement. Clear error messages showing which rule matched. |
| **Audit log grows unbounded** | 2 | Low | Rotate logs at 10MB. Keep last 3 files. Document log rotation. |
| **Telemetry report contains unexpected PII** | 3 | High | Automated PII scan in CI. `team_id` is team-chosen, not derived from user. `active_users` is a count, not a list. |
| **`enforce_team_vaults_only` blocks legitimate personal use** | 2 | Medium | Document that this is an enterprise policy setting. Default is `false`. Provide `agk install --force` override with audit logging. |
